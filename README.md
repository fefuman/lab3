# Лабораторная: общий счётчик между процессами

Небольшой проект на C++17 без внешних библиотек. Каждый экземпляр процесса увеличивает общий счётчик раз в 300 мс и принимает целые числа из stdin. Первый запущенный экземпляр становится лидером: он раз в секунду пишет снимок счётчика в журнал и каждые три секунды запускает не более одной копии каждого вида.

- Копия A добавляет 10 и завершается.
- Копия B умножает значение на 2, ждёт 2 секунды, делит текущее значение на 2 и завершается.
- Если предыдущая копия того же вида ещё работает, лидер пишет `SKIP` в журнал.

## Сборка

Нужны CMake 3.16+ и компилятор с поддержкой C++17.

### Ubuntu 20.04

```sh
sudo apt update
sudo apt install build-essential cmake
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/os_counter
```

В другом терминале можно запустить ещё один экземпляр: `./build/os_counter`. Введите целое число и нажмите Enter, чтобы установить общий счётчик. `Ctrl+C` останавливает экземпляр. Установка счетчика доступна во всех экземплярах.

### Windows (MSYS2 UCRT64)

Откройте терминал **MSYS2 UCRT64**, установите инструменты и соберите проект:

```sh
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake make
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/os_counter.exe
```

Запустите второй `os_counter.exe` в другом терминале. Счётчик вводится в консоль процесса. `Ctrl+C` освобождает лидерство.

## Файлы состояния и журнала

По умолчанию Ubuntu использует `/tmp/os_counter_lab_<uid>/`, Windows — временную папку `%TEMP%\os_counter_lab`. В ней находятся `state.bin` и `counter.log`. Чтобы явно задать пути (они должны совпадать у всех экземпляров):

```sh
./build/os_counter --state ./run/state.bin --log ./run/counter.log
```

При тестах удалите эти файлы только после остановки всех экземпляров. Журнал пополняется, а счётчик сохраняет последнее значение между запусками.

## Архитектура и гонки

Счётчик и лидерство лежат в фиксированной структуре общего state-файла. Каждый доступ к структуре выполняется под эксклюзивной межпроцессной блокировкой: `flock` на POSIX и `LockFileEx` на Windows. Поэтому инкремент, установка числа, операции копий и проверка/назначение лидера сериализуются; обновления счётчика не теряются. Блокировка короткоживущая — её не удерживают во время ожидания копии.

Журнал защищается отдельным блокируемым файлом `counter.log.lock`, поэтому строки разных процессов не смешиваются. Лидер хранит PID активных копий A/B и перед очередным стартом проверяет их существование. При остановке лидера его PID сбрасывается под блокировкой; другой экземпляр сможет занять роль. PID-проверка имеет обычное системное ограничение: теоретически ОС может повторно выдать уже освобождённый PID.

Промежуточный снимок для строки `TICK` читается атомарно, затем записывается в журнал; значение может успеть измениться до момента записи строки. Все изменения при этом остаются защищёнными. Операция B делит актуальное значение через 2 секунды, поэтому изменения, сделанные за это время другими экземплярами, тоже участвуют в делении. Для отрицательных и нечётных чисел используется целочисленное деление C++.

Лидерство действует между экземплярами, использующими один и тот же state-файл. Не запускайте процессы с одинаковым state-путём и разными журналами, если требуется единый согласованный набор настроек.

## Проверка вручную

1. Запустите два экземпляра с одинаковыми путями `--state` и `--log`.
2. Введите число в каждой консоли: обе команды должны отражаться в общем логе как `SET`.
3. Убедитесь, что `TICK` и `START child-*` пишет один PID-лидер.
4. Проверьте, что за запуск B в журнале есть `START` и `EXIT` с интервалом примерно 2 секунды.
5. Остановите лидера и проверьте, что другой экземпляр записывает новую строку `LEADER` и продолжает циклы.
